4 The factory swap

mcp_server_ol/src/mcp_server_ol/main.py install(), lines 82–124

postgres_mcp.server.get_sql_driver is a module-level factory, so install() replaces it with one returning a LineageSqlDriver. Upstream is not forked, not vendored, not modified; it stays pinned (RAID D03). "Adding OpenLineage to a real, widely-adopted MCP server is a subclass and a factory swap."

In RESTRICTED mode upstream wraps the driver in a SafeSqlDriver, so install() reaches through getattr(driver, "sql_driver", driver) and instruments whichever object actually reaches the database.

5 Instrumentation — LineageSqlDriver we instrument here

subclass of postgres_mcp.sql.SqlDriver · mcp_server_ol/src/mcp_server_ol/driver.py lines 115–222

This is the choke point: all nine tools funnel through execute_query, which is why one subclass covered the whole server. (Not to be confused with driver/driver.py, the unrelated test client in stage 1 — README.md notes the naming collision explicitly.)

  1. Open the OTel span. telemetry.tracer().start_as_current_span(self._job_name), default job name mcp.execute_sql, service resource mcp-server-ol (telemetry.py:48).
  2. Parse. parse_statement(sql) → openlineage_sql.parse([sql], dialect="postgres"). A parse failure is not fatal — the statement still runs and lineage is emitted with no datasets, tagged parse-failed, counted via telemetry.record_degraded(...). It must not read as "this touched nothing" (RAID I29).
  3. Resolve caller identity. self._parent() → main._current_parent() → meta.parent_from_meta(...). A provider that raises is our own instrumentation failing, counted as Dropped.NO_REQUEST_CONTEXT — never folded into the normal absent case.
  4. Mint the run id. emitter.new_run_id() → uuid4. Span attributes lineage.run_id and lineage.actor_status go on immediately — correlation, not identity (RAID R09).
  5. Emit START — before execution.→ Marquez A process killed mid-statement still leaves a record that the database was reached. This ordering is what makes fail-closed coherent rather than theatrical.
  6. Execute.→ Postgres await super().execute_query(...) → psycopg / psycopg_pool → warehouse.obsinsure.*.
  7. Emit the terminal event. COMPLETE on success; on exception FAIL with an errorMessage facet, then re-raise. The FAIL path is forced fail-open in both postures (force_open=True) — an emission failure must never mask the real database error.

5a — the failure posture, off _safe_emit

OPEN — default, RAID D11A lineage failure is recorded and swallowed. An observability side-channel that can break the thing it observes gets removed by the first person it pages.
CLOSED — RAID R08, LINEAGE_FAILURE_MODE=closedThe statement is refused rather than left unrecorded, raising LineageEmissionError — distinct from any database error, because the statement was fine and the control failed.

The drop counter is recorded in both modes, before the mode is consulted — the one path where OpenLineage cannot report on itself. Neither mode is presented as correct; both are demonstrated.

6 What the OpenLineage event carries

mcp_server_ol/src/mcp_server_ol/lineage.py

RunEvent
eventType = START | COMPLETE | FAIL, built with openlineage-python — never hand-rolled JSON.
Job
namespace mcp-lineage-demo (OL_JOB_NAMESPACE), name mcp.execute_sql, with an SQLJobFacet carrying the query text.
Datasets
namespace postgres://{host}:{port}, name {database}.{schema}.{table} — e.g. postgres://postgres:5432 / warehouse.obsinsure.claim. Per the OpenLineage naming specification (naming.py): a canonical catalog identity, not a transport pointer (RAID A05) — the earlier scaffold got this wrong (I16).
ParentRunFacet
present only when the caller supplied identity. Linkage only (RAID D10): the caller's identity facets are deliberately not forwarded nested inside it, because the pinned Marquez silently discards them (R07, I22).

TagsRunFacet — three tags, all standard facets

A04 was wrong precisely because it proposed something new without checking what already existed.

lineage.derivation = parsed-intent lineage.completeness = not-guaranteed | parse-failed lineage.actor = supplied | absent | malformed

Datasets are parsed intent, not observed effect (RAID D08). Views, triggers, cascades, partition routing and RLS are invisible to a parser (R03). Emitting intent unlabelled would make this demo an instance of the problem it describes.
